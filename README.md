# Nozie - Movie Streaming Platform

> **→ Upgraded version (Nozie Platform - Microservices with Java Spring):** [ndviet0303/SA25-26_ClassN02_Group_3](https://github.com/ndviet0303/SA25-26_ClassN02_Group_3)

A movie streaming app: a Flutter client (mobile + web) talking to a Spring Boot API backed by PostgreSQL.

## Repository layout

```
nozie/
├── apps/mobile/        Flutter app (android, ios, web)
├── services/api/       Spring Boot REST API (Java 21, Maven, PostgreSQL, Flyway, JWT)
├── tools/
│   └── import-firestore/   one-off migration: Firestore movies -> PostgreSQL
├── contracts/openapi.json  API contract, generated by the API tests; the client is built against it
├── infra/              docker-compose (postgres, mailhog, minio, api) and .env.example
├── docs/               design notes
└── .github/workflows/  CI: api, mobile, tools, secret scan
```

Responsibilities are split strictly: **the server decides** prices, access rights and identity; **the client only
displays** and sends intent (`movieId`, never `userId` or an amount). See [services/api/README.md](services/api/README.md)
for the server layers.

## Quick start

```bash
# 1. infrastructure
cp infra/.env.example infra/.env            # then set JWT_SECRET etc.
docker compose -f infra/docker-compose.yml up -d postgres mailhog

# 2. API  (http://localhost:8080, Swagger UI at /swagger-ui.html in the dev profile)
cd services/api
DB_URL=jdbc:postgresql://localhost:${POSTGRES_PORT:-5432}/nozie DB_USER=nozie DB_PASSWORD=change-me-dev-only \
JWT_SECRET=$(openssl rand -base64 48) \
  mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 3. app
cd apps/mobile
cp env/dev.example.json env/dev.json
flutter run --dart-define-from-file=env/dev.json
```

## Tests

| Part | Command |
|---|---|
| API (needs Docker for Testcontainers) | `cd services/api && mvn verify` |
| Mobile | `cd apps/mobile && flutter analyze && flutter test` |
| Import tool | `cd tools/import-firestore && npm test` |

`mvn verify` regenerates `contracts/openapi.json`; commit it when the API changes (CI fails if it is stale).

## Migration status (Firebase -> own backend)

Done: the Flutter app no longer depends on Firebase. Authentication, catalog (home, discover, search, genres,
similar, recommended), movie detail, reviews and likes, wishlist, purchases and Stripe checkout, playback access,
watch history, notifications, profile and avatar, and playback problem reports all go through the Spring API.
`firebase_*` / `cloud_firestore` are removed from `pubspec.yaml`.

Still to do:
- Run `tools/import-firestore` against the real Firestore export to fill the catalog (and move legacy wishlist,
  purchases and ratings keyed by Firestore ids).
- Movie backdrop gallery (was `images/{id}` in Firestore) is not in the API yet, so that section was removed.
- iOS: run `pod install` once to drop the stale Firebase pods from `ios/Podfile.lock`.
- Per-device session list ("sign out device"), payment methods and notification preferences are still local
  placeholders in the app.
